手写 AI Agent 核心模块：模型、工具、记忆与上下文工程
当你理解了 Agent 的最小循环，下一步就是手写核心模块。零基础原生开发不需要一开始追求大而全，但必须把模型抽象、工具协议、记忆系统和上下文工程这四块做扎实。它们决定了 Agent 是否稳定、可扩展、可调试，也决定了你能否摆脱对现成框架的依赖。

模型抽象是入口。不同模型在上下文长度、推理能力、响应速度、价格和工具调用格式上差异很大。原生开发应定义统一接口，把模型调用、重试、超时、流式输出、令牌计数和错误分类封装起来。这样上层循环不关心具体供应商，换模型时只改适配层。更重要的是模型路由：简单分类走小模型，复杂规划走强模型，敏感数据走私有化模型，重复问题走缓存。模型不是越强越好，而是要与任务匹配。手写抽象层还能让你精确控制提示结构和停止条件，避免框架自动拼接带来的不可控。

工具协议是 Agent 的手脚。一个工具至少要有名称、描述、参数结构、执行器、权限、超时、幂等策略和返回格式。描述要告诉模型“什么时候用”，参数结构要严格校验，执行器要捕获异常并返回可读结果。工具分三类：只读工具、写入工具和高危工具。只读工具可以自动执行；写入工具需要幂等和回滚；高危工具必须二次确认或转人工。原生开发时，不要依赖框架自动生成工具描述，而要亲手设计协议。因为工具描述的质量，直接决定模型会不会误调、漏调或重复调。工具越多，越要分组、限权和监控。

记忆系统是 Agent 的经验。短期记忆保存当前对话和工具结果，长期记忆保存知识库、历史任务和用户偏好，工作记忆保存当前任务的待办、依赖和中间结论。原生实现可以用摘要压缩短期记忆，用向量检索长期记忆，用结构化状态保存工作记忆。关键不是存储技术，而是写入和召回策略：什么值得记、什么时候记、召回多少、如何避免污染。记忆过多会导致上下文膨胀和注意力分散，记忆过少又会让 Agent 反复提问。好的记忆系统应像人类工作记忆，只保留与当前目标相关的信息。

上下文工程是核心中的核心。模型能力再强，上下文错了，结果也会错。原生开发要定义上下文的层次：系统规则、角色设定、任务目标、历史摘要、检索证据、工具结果、当前指令。每层有不同优先级和裁剪策略。上下文窗口有限时，优先保留系统规则和当前目标，压缩历史，按相关性召回证据。要明确区分事实、假设和待确认项，避免模型把猜测当结论。还要处理上下文冲突：检索结果与用户说法不一致时，应提示矛盾而非强行回答。引用溯源、拒答机制和敏感信息过滤，也应在这一层完成。

最后是执行器与可观测性。执行器负责调度模型和工具，支持串行、并行、重试、降级和回滚。每一步都要记录输入、输出、耗时、令牌和结果，形成可追踪轨迹。零基础手写 Agent，最忌讳只关注“能不能跑”，而忽略“为什么这样跑”。只有把模型、工具、记忆和上下文模块化，才能独立测试、替换和优化。原生开发的意义，不是重复造轮子，而是掌握轮子如何转。能亲手设计这些核心模块，你才能真正控制 Agent 的行为、成本和安全。
